# Yagya Krishi Udhyog — static business website

A production-ready, responsive, **English-only static website** for
**Yagya Krishi Udhyog** — a Nepali agricultural business working in livestock,
animal-feed dealership and seasonal crops.

Every page is a **self-contained HTML file at the site root**. There is no build
step, no framework, no bundler, and **no content generated by JavaScript** — the
text, catalogue entries, filters and search live in the markup, and JavaScript is
used only for behaviour (menus, filtering, motion, cookie bar, form hand-off).

> **Placeholder content:** catalogue text, availability labels and the
> `example.com` domain are samples. Replace them with confirmed information from
> the business owner before launch. No prices, certifications, statistics or
> testimonials are invented anywhere on the site. Images are real
> copyright-free photographs (see §12).

---

## 1. Quick start

Serve the folder over HTTP (recommended):

```bash
# Python 3
python -m http.server 8080

# or Node
npx serve .
```

Then open <http://localhost:8080/>. Opening `index.html` straight from
`file://` also works.

## 4. How a page is put together

Every page repeats the same skeleton. The header and footer are **written
directly into each file** — there is no component file, template include or JS
injection:

```html
<body class="page-detail">
  <header class="site-header" id="site-header"> … </header>

  <div data-scroll-container>
    <main id="main"> … page sections … </main>
    <footer class="site-footer" id="site-footer"> … </footer>
  </div>

  <!-- scripts at the end of <body>, all deferred -->
</body>
```

* The header is `position: fixed` and sits **outside** `[data-scroll-container]`;
  `body` reserves space with `padding-top: var(--header-h)`.
* `[data-scroll-container]` wraps `main` + `footer` and is what Locomotive Scroll
  moves.
* Because the chrome is inline, a change to navigation/footer must be applied to
  **all 36 pages**. This repository is emitted by a small Node generator that
  lives **outside** the repo (it is a build-time convenience only — the site
  does not depend on it); if you don't have it, edit the HTML directly.

### Script wiring

Shared on every page:

```
Locomotive Scroll (vendored) → navigation-static.js → cookie.js → animations.js
```

Page-specific scripts are added only where needed:

| Marker in the markup | Script | Pages |
| --- | --- | --- |
| `data-controls` | `filters-static.js` | 3 catalogues |
| `data-detail-gallery` | `detail.js` | 20 detail pages |
| `data-gallery` | `gallery.js` | Home |
| `id="lead-form"` | `contact-static.js` | Contact |
| `id="search-index"` | `search.js` | Search |
| `class="accordion"` | `accordion.js` | 5 |

GSAP, ScrollTrigger and Swiper are loaded from jsDelivr; Locomotive Scroll is
vendored locally under `assets/js/vendor/` and `assets/css/vendor/`.

## 5. Motion

`assets/js/animations.js` boots **Locomotive Scroll** for smooth page scrolling
and **GSAP + ScrollTrigger** (with a `scrollerProxy`) for reveals. It:

* adds a shadow to the header once scrolled (`header.is-scrolled`);
* reveals hero text, media and section blocks on entry;
* exposes `window.YK_LOCO` for other scripts;
* **does nothing** when the visitor sets `prefers-reduced-motion: reduce`, or if
  Locomotive/GSAP fail to load — the page then behaves as a plain static
  document with normal browser scrolling.

The home gallery uses Swiper only below 768px; desktop uses the same images with
a lightbox.

---

## 6. Cookie consent

`assets/js/cookie.js` appends a fixed bar at the bottom of the viewport with
**Accept** and **Decline** buttons. The choice is stored under
`yk_cookie_consent` in `localStorage` and the bar is not shown again once a
choice is made. The bar is injected by JS (so it is absent when JS is off) and
is described in the privacy policy.

---

## 7. Site search

`search.html` contains a **static `<ul id="search-index">`** listing every page
with a section label and keywords — the page returns results without
JavaScript. `assets/js/search.js` reads that list once (then removes it from the
DOM), filters it live as you type, highlights matches, syncs the query to the URL
(`search.html?q=…`) so results are linkable, and supports keyboard navigation.

## 8. The contact form (WhatsApp hand-off)

`contact.html` collects an enquiry and hands it to WhatsApp — the site never
pretends a message was sent by itself.

* Required fields are validated in the browser (no backend).
* A pre-filled message is composed and opened via
  `https://wa.me/9779804331857?text=…` in a new tab.
* If the pop-up is blocked, a fallback link and a clear notice are shown.
* The form remembers a draft in `localStorage` (`yk_enquiry_draft`) and clears it
  after a successful hand-off.
* Catalogue “Enquire” buttons deep-link into the form so the item is
  pre-selected.

Every WhatsApp link in the site carries `data-wa-link`; `contact-static.js`
rewrites those `href`s with the current phone number so the number lives in **one
place in JS** plus the visible markup.

## 10. Accessibility

* Semantic landmarks (`header`, `nav`, `main`, `footer`) and a skip link on every
  page.
* Visible focus rings, keyboard-operable menus, a drawer and lightbox with focus
  management.
* Interactive state (mobile sub-nav, lightbox, form feedback, accordion panels)
  is toggled with classes / `aria` rather than the `hidden` attribute, so
  keyboard and screen-reader state stay correct.
* Colour contrast targets WCAG AA. Motion respects `prefers-reduced-motion`.

## 12. Images and licensing

Real, copyright-free photographs live in `assets/images/photos/`. Each slot has a
full-size file (`<id>.jpg`) and a card/thumbnail (`<id>-card.jpg`), used via
`srcset`. `credits.json` (in the same folder) records the source, creator and
licence for every photo; the human-readable credits are listed in
`privacy-policy.html#image-credits`.

To swap a photo, replace both files for that slot (keep the filenames). To add a
new slot, add the two files, add a `credits.json` entry and reference it from the
page. Keep a roughly 4:3 / 3:2 ratio; the CSS crops with `object-fit: cover`.

`assets/images/logo/logo.png` is the logo **and** the favicon — replace it with
the real brand mark.

## 13. Editing content

Content lives in the HTML, per page:

| To change… | Edit… |
| --- | --- |
| Any page's copy | the relevant `.html` file |
| Navigation or footer (all pages) | the `<header>` / `<footer>` block in every `.html` file |
| A catalogue item | its card/row on the catalogue page **and** its detail page |
| Phone / WhatsApp number | search for `9779804331857` and `+977-980-433-1857` |
| Domain / canonical URLs | `sitemap.xml`, `robots.txt` and every page's `<link rel="canonical">` + `og:*` tags |
| Search results | the `<ul id="search-index">` in `search.html` |
| Image credits | `credits.json` and `privacy-policy.html#image-credits` |

Because a page is plain HTML, anything you can write by hand you can also produce
with your own templating if you prefer.

## 14. Deployment

Upload the whole folder to any static host (Netlify, Vercel, GitHub Pages,
Cloudflare Pages, or classic shared hosting). There is no build step.

Checklist:

1. Set the real domain in `sitemap.xml`, `robots.txt` and every page's
   canonical / `og:url`.
2. Replace `assets/images/logo/logo.png` with the real logo (and favicon).
3. Confirm catalogue text, availability and the real photos.
4. Confirm the phone number and WhatsApp number.
5. Re-verify the privacy policy and terms reflect the real business.
6. Test the lead form on a real phone and confirm the WhatsApp hand-off.
7. Update the `#image-credits` list if you swap photos.

## 15. Browser support

Evergreen Chrome, Edge, Firefox and Safari, plus mobile browsers. The site uses
modern CSS (custom properties, `clamp()`, grid, `aspect-ratio`) and plain
ES5-level JavaScript, and degrades gracefully — with JS disabled you still get
the full content, working links and searchable markup.
